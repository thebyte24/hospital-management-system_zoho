# Data Store Schema - Hospital Queue Management

## ⚠️ CRITICAL NOTES

1. **Tables MUST be created manually** in the Catalyst Console
   - Navigate to: **Cloud Scale → Data Store**
   - Click **"Create Table"**
   
2. **Do NOT create an ID column**
   - Catalyst automatically creates `ROWID` as the primary key
   - Never define your own ID field

3. **Use exact names** (case-sensitive)
   - Table names: `Patients`, `Doctors`, `Visits`
   - Column names as specified below

4. **Create tables in any order**
   - No foreign key constraints need to be defined
   - References are handled in application code

---

## Table 1: Patients

**Table Name**: `Patients`

| Column Name | Data Type | Required | Description | Example |
|-------------|-----------|----------|-------------|---------|
| Name | Text | Yes | Patient's full name | "John Doe" |
| Age | Number | Yes | Patient's age in years | 45 |
| Gender | Text | Yes | Gender | "Male" |
| Phone | Text | Yes | Contact phone number | "555-0123" |
| BloodGroup | Text | No | Blood group | "A+" |
| UserID | Text | No | Catalyst user ID (empty for walk-ins) | "12345678" |

### Notes
- `UserID` is populated when a patient self-registers through the app
- Walk-in patients registered by reception have empty `UserID`
- ROWID is auto-generated by Catalyst

---

## Table 2: Doctors

**Table Name**: `Doctors`

| Column Name | Data Type | Required | Description | Example |
|-------------|-----------|----------|-------------|---------|
| Name | Text | Yes | Doctor's full name | "Dr. Sarah Johnson" |
| Specialization | Text | Yes | Medical specialization | "General Medicine" |
| Email | Email | Yes | Doctor's email address | "sarah@hospital.com" |
| Phone | Text | Yes | Contact phone number | "555-0101" |
| UserID | Text | Yes | Catalyst user ID (linked to Doctor role) | "87654321" |

### Notes
- `UserID` links to a Catalyst user with the "Doctor" role
- Doctors are invited by admin through Catalyst Console
- After invitation, admin creates the Doctor record with their UserID

---

## Table 3: Visits

**Table Name**: `Visits`

| Column Name | Data Type | Required | Description | Example |
|-------------|-----------|----------|-------------|---------|
| PatientID | Text | Yes | ROWID of patient from Patients table | "1234567890123" |
| DoctorID | Text | Yes | ROWID of doctor from Doctors table | "9876543210987" |
| VisitDate | Date | Yes | Date of visit | "2026-07-30" |
| Reason | Text | Yes | Reason for visit / symptoms | "Fever and cough" |
| Status | Text | Yes | Current visit status | "Waiting" |
| Priority | Text | Yes | Priority level | "Normal" |
| CheckInTime | DateTime | No | When patient checked in | "2026-07-30T14:23:00Z" |
| ConsultStartTime | DateTime | No | When consultation started | "2026-07-30T14:45:00Z" |
| ConsultEndTime | DateTime | No | When consultation ended | "2026-07-30T15:00:00Z" |
| Notes | Text | No | Doctor's consultation notes | "Prescribed antibiotics..." |

### Valid Values

#### Status
- `"Waiting"` - Patient in queue
- `"In Consultation"` - Currently with doctor
- `"Completed"` - Consultation finished

#### Priority
- `"Normal"` - Standard priority
- `"Urgent"` - High priority (appears first in queue)

### Automatic Timestamps

The application automatically sets:
- `CheckInTime` when visit is created (patient checks in)
- `ConsultStartTime` when Status changes to "In Consultation"
- `ConsultEndTime` when Status changes to "Completed"

## Table Creation Steps (Catalyst Console)

### For Each Table:

1. **Navigate to Data Store**
   - Open Catalyst Console
   - Go to: **Cloud Scale → Data Store**

2. **Create New Table**
   - Click **"Create Table"** button
   - Enter table name (exact spelling from above)

3. **Add Columns**
   - Click **"Add Column"** for each column
   - Enter column name (exact spelling)
   - Select data type from dropdown
   - Set required/optional
   - Click **"Save"** for each column

4. **Verify ROWID**
   - After saving table, verify `ROWID` column appears
   - This is auto-generated, do not create manually

5. **Save Table**
   - Click **"Save Table"**
   - Table is now ready

## Relationships

```
Patients ──< Visits >── Doctors
   │                      │
   │                      │
  ROWID                 ROWID
   │                      │
   └─ PatientID          └─ DoctorID
      (in Visits)           (in Visits)
```

- One patient can have many visits
- One doctor can have many visits
- Each visit belongs to one patient and one doctor

## Common Mistakes to Avoid

❌ **Don't**: Create an "ID" column  
✅ **Do**: Use auto-generated ROWID

❌ **Don't**: Use lowercase table names ("patients")  
✅ **Do**: Use exact case ("Patients")

❌ **Don't**: Create foreign key constraints  
✅ **Do**: Store ROWIDs as Text references

❌ **Don't**: Try to create tables via code  
✅ **Do**: Create tables manually in console

❌ **Don't**: Forget to create all 3 tables  
✅ **Do**: Create Patients, Doctors, AND Visits
